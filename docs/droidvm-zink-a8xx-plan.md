# DroidVM A8xx Zink / Freedreno optimization plan

## Current architecture

The current Mesa architecture does not contain a direct Zink-to-Freedreno OpenGL
backend migration. The supported path remains:

```
OpenGL application
        |
       Zink
        |
 Vulkan loader / Turnip
        |
 Freedreno Vulkan backend
        |
 A8xx GPU
```

A native OpenGL Freedreno Gallium path is a separate Gallium driver path and
would not be a Zink migration.

## Phase 1: Zink -> Turnip hot path profiling

The first optimization phase keeps the existing architecture and measures:

- Zink pipeline creation duplication.
- NIR conversion and shader variant reuse.
- Descriptor/pipeline layout churn visible from Vulkan.
- Turnip command submission batching.
- Freedreno A8xx shader lowering overhead.

No new OpenGL backend is introduced in this phase.

## Phase 2: A8xx-specific tuning

Candidate changes:

- Avoid redundant Vulkan state transitions generated by common OpenGL patterns.
- Improve pipeline cache reuse for long-running OpenGL workloads.
- Tune descriptor lifetime behavior for DroidVM workloads.
- Compare Zink workloads against native Gallium Freedreno workloads where
  available.

## Acceptance criteria

A change is only accepted after:

1. Mesa Linux build passes.
2. ARM64 Turnip build passes.
3. Same workload is compared with fixed shader cache and driver revisions.
4. No Vulkan ABI or DroidVM Native Context ABI changes are introduced.

FPS improvements will only be reported after real device measurements.
